> 版本：V1.0｜日期：2026-10-25
>
> 配套文档：`产品功能设计文档（V1.0）.md`
>
> 阅读提示：本文说明“谁、在什么场景、要完成什么、必须遵守什么规则”。页面布局、交互细节和数据对象见产品功能设计文档。本文只写产品行为，不写接口、数据库字段和测试步骤。

## 0 一分钟看懂

PaperLens 是一个论文检索与阅读工作台：

1. 管理员把 PDF 论文导入“全局论文目录”，并在后台维护目录、账号和私有仓库。
2. 用户在主页输入研究方向，或上传一个 PDF 作为查询。
3. 系统从全局目录检索相关论文和原文证据，自动进入“会话工作区”。
4. 会话里有三个视图：对话、论文总结、相关仓库。
5. 用户可以把论文集合建为仓库，公开或私有；仓库里的论文来自全局目录，不能上传。
6. 每篇论文都有四维总结（问题、前人研究、方法/创新、不足），按需生成，跨页面共享。
7. 对话分为三种范围：本次会话、当前仓库、单篇论文；回答必须带引用，没有证据就拒答。

**V1.0 不设论文数量、仓库容量、检索范围档位等数量限制。** 这些作为后续扩展，不进入本期 P0。

## 1 产品定位

### 1.1 一句话

输入一个问题，得到一组可追溯的相关论文；围绕这组论文读总结、做比较、继续追问，并把它们整理成自己的公开或私有仓库。

### 1.2 解决的问题

- 论文太多，不知道哪些和当前方向相关；
- 读完记不住每篇的问题、方法、创新和不足；
- 通用聊天没有出处，无法回到原文核对；
- 收藏和整理散落在不同工具里，难以形成可共享的论文集合；
- 单篇精读和领域调研之间来回切换成本高。

### 1.3 不解决的问题

- 不做论文上传、网盘、文献管理器的全量替代；
- 不做自动写综述、自动生成论文；
- 不做论文图谱、引用关系图、研究演化图；
- 本期不做图片：图片型 PDF、扫描件、截图不解析，也不做 OCR；只读取 PDF 文本层。
- 不做团队协作编辑、评论、分享链接；
- 不做自动评测、课程验收类功能、部署和运维。

## 2 核心概念

| 概念 | 说明 | 关键边界 |
| :--- | :--- | :--- |
| 全局论文目录 | 管理员导入的全部论文，是全局搜索的唯一来源 | 所有登录用户都能搜索、查看详情、下载和单篇对话 |
| 仓库 | 用户从全局目录挑选论文形成的集合 | 不是上传空间；只能添加已有论文；公开或私有 |
| 会话 | 一次全局查询产生的论文集合、证据和对话空间 | 会话保存当时的证据快照，后续查询不会修改它 |
| 证据 | 进入会话或回答的原文片段 | 用于引用和回到原文；没有证据时不能编造 |
| 四维 | 问题、前人研究、方法/创新、不足 | 论文级总结，跨会话、仓库、详情共享，不按用户或会话重做 |
| 三种对话 | 会话对话、仓库对话、单篇论文对话 | 三者的检索范围严格隔离，不能互相越界 |
| Star | 对公开仓库的推荐信号 | 不是收藏；只对公开仓库、不能 star 自己的仓库 |
| PDF 查询 | 首页上传 PDF，只提取文字作为本次查询 | 不入库、不进仓库、不保存为论文 |
| Agent | 仓库对话中的只读检索助手 | 只在当前仓库内检索，不访问全局目录、不联网、不写数据 |

## 3 角色与权限

| 角色 | 说明 | 能做什么 | 不能做什么 |
| :--- | :--- | :--- | :--- |
| 游客 | 未登录访问者 | 只能看到登录页 | 不能搜索、查看论文、进入仓库或对话 |
| 普通用户（reader） | 由管理员创建账号的用户 | 全局搜索、查看会话、创建和管理自己的仓库、star 公开仓库、仓库对话、单篇对话、下载论文 | 导入论文、管理用户、进入管理后台、读取他人的私有仓库 |
| 管理员（admin） | 负责论文目录、账号和私有仓库的管理员 | 普通用户的全部能力；导入和维护全局论文目录；管理用户；查看管理总览；查看和管理私有仓库（集合、对话、信息、论文、删除） | 不能编辑公开仓库；不提供评测、审计和部署功能 |

补充规则：

- 账号只能由管理员创建，不开放自注册。
- 普通用户可以创建多个仓库；仓库归创建者所有。
- 公开仓库对所有登录用户可见、可对话、可 star；只有创建者能编辑。
- 私有仓库只有创建者和管理员可见、可对话；不出现在公开列表和推荐中；不能 star；普通用户不能读取其内容。
- 论文的可见性由全局目录决定，与它被放进哪个仓库无关。私有仓库对普通用户隐藏“这个集合和这段对话”，不隐藏论文本身；管理员因管理需要可以查看集合和对话。
- 所有权限在服务端判断；页面隐藏按钮不能代替权限判断。无权访问时不返回资源名称、数量等元信息。

## 4 核心使用路径

### 4.1 全局调研

```text
登录
→ 主页输入方向/问题，或上传 PDF 作为查询
→ 系统在全局论文目录中检索
→ 生成会话：相关论文 + 原文证据
→ 自动进入会话工作区
→ 在“对话”里追问，在“论文总结”里看四维，在“相关仓库”里找别人的收藏
→ 点引用或论文标题进入详情，下载原文
```

### 4.2 整理自己的仓库

```text
主页或会话中创建仓库
→ 填写名称、简介、公开/私有
→ 从全局论文目录搜索并添加论文
→ 打开仓库：左侧论文列表，右侧对话面板
→ 围绕整个仓库提问，回答带引用
→ 公开仓库可被其他用户 star；私有仓库默认只属于自己，管理员可因管理需要查看
```

### 4.3 单篇精读

```text
从会话、仓库或搜索结果点进论文详情
→ 查看元数据、摘要和四维总结
→ 下载原文
→ 围绕这一篇论文提问
→ 点引用回到原文位置
```

### 4.4 管理员维护目录

```text
管理员登录
→ 上传 PDF
→ 查看解析/索引状态，失败可重试
→ 修正标题、作者、年份、期刊/会议等元数据
→ 论文进入全局目录，用户可搜索
→ 在后台管理用户
```

### 4.5 管理员管理私有仓库

```text
管理员进入后台
→ 仓库管理
→ 打开私有仓库
→ 查看论文集合和对话
→ 编辑信息、增删论文或删除仓库
→ 公开仓库保持只读
```

## 6 用户故事详情

### 6.1 账户与权限

#### AUTH-01 登录

**故事**：作为被管理员创建账号的用户，我希望用邮箱和密码登录，以便进入自己的工作台。

**规则**：

- 只支持本地账号密码登录；账号由管理员创建，不开放自注册。
- 登录成功后进入主页；未登录访问业务页面时回到登录页。
- 登录失败只提示“邮箱或密码错误”，不说明账号是否存在。
- V1.0 不做 SSO、LDAP、TOTP 和多因素认证。

#### AUTH-02 退出与当前用户

**故事**：作为用户，我希望随时退出，并确认当前登录的是谁。

**规则**：

- 顶部用户菜单可以退出；退出后清除登录状态并回到登录页。
- 刷新页面后仍能识别当前用户；登录过期时回到登录页。
- 未登录用户看不到任何论文、仓库或对话内容。

#### AUTH-03 角色与权限边界

**故事**：作为系统，我需要区分普通用户和管理员，并控制私有内容的访问。

**规则**：

- 角色只有普通用户（reader）和管理员（admin）。
- 普通用户可以搜索、查看会话、创建和管理自己的仓库、star 公开仓库、进行三种对话、下载论文。
- 管理员拥有普通用户能力，并额外负责全局论文目录、用户管理、管理总览和私有仓库管理。
- 管理员可以查看和管理私有仓库的论文集合与对话；普通用户仍然只能访问自己的私有仓库。
- 公开仓库可以被所有登录用户查看、对话和 star；只有创建者可以编辑。
- 权限在服务端判断；无权访问时不返回资源名称、数量等元信息。

#### AUTH-04 用户管理

**故事**：作为管理员，我希望创建和停用账号，以便控制谁可以使用系统。

**规则**：

- 管理员可以查看用户列表，创建普通用户或管理员，修改显示名和角色。
- 管理员可以停用账号；停用后不能登录，已有历史记录保留。
- 管理员可以重置密码；不提供用户自注册和自助找回密码。
- 不删除用户，不做审计日志，不做复杂运营报表。

### 6.2 全局论文目录

#### KB-01 管理员导入论文

**故事**：作为管理员，我希望把 PDF 论文导入全局目录，以便所有用户都能搜索。

**规则**：

- 只有管理员可以导入；普通用户在任何页面都不能上传论文。
- 导入的是 PDF，进入全局论文目录，不直接进入某个仓库。
- 本期只处理带文本层的 PDF，只读取文字层；图片型 PDF、扫描件、截图不解析，不做 OCR。
- 支持一次选择多个文件；单个文件失败不影响其他文件。
- 重复论文复用已有目录记录，不重复创建。
- 导入后显示处理状态；用户可以在论文就绪后搜索到它。

#### KB-02 解析、索引与失败重试

**故事**：作为管理员，我希望看到论文从上传到可搜索的过程，并能处理失败。

**规则**：

- 处理状态包括：排队、解析、索引、就绪、失败。
- 系统从 PDF 中提取标题、作者、年份、期刊/会议、摘要等元数据，并建立可检索的原文索引。
- 处理完成后论文进入全局目录；处理中的论文不出现在搜索结果里。
- 失败时显示原因，管理员可以单篇重试。
- 解析质量不足时，管理员可以修正元数据或重新导入；不承诺图片、扫描件和复杂版式。

#### KB-03 论文目录维护

**故事**：作为管理员，我希望修正论文信息和处理旧论文，以便目录长期可用。

**规则**：

- 管理员可以按标题搜索目录，查看论文状态和元数据。
- 管理员可以修正标题、作者、年份、期刊/会议、摘要等元数据。
- 管理员可以归档论文：归档后不再出现在新的全局搜索和新的仓库添加中。
- 已归档论文如果已经出现在旧会话或旧仓库中，仍然可以打开详情、查看引用；原文文件保留时仍可下载，避免旧内容断裂。
- 默认使用归档而不是物理删除；不做审计日志和复杂版本历史。


### 6.3 搜索与会话

#### SRCH-01 主页文字/PDF 查询

**故事**：作为用户，我希望在主页直接描述研究方向，或拿一篇 PDF 当例子，快速找到相关论文。

**规则**：

- 主页输入框支持文字查询，例如研究方向、关键词、论文标题或一句问题。
- 主页可以上传一个 PDF 作为查询；系统只提取其中的文字来理解查询。
- 首页 PDF 只用于本次查询：不入库、不加入全局目录、不加入仓库、不保存为论文。
- 如果 PDF 没有可读文字，提示无法读取，并建议改用文字查询；本期不做图片识别和 OCR。
- 全局查询的范围是全部全局论文目录，不是“我的仓库”或“我可见的仓库”。
- 主页不提供年份、期刊级别、论文类型等筛选；本期只通过查询词表达需求。
- 主页展示最近会话、我的仓库、公开仓库；管理员额外看到管理入口。
- 提交查询后显示检索进度；成功后自动进入会话；没有结果时也进入会话的空状态，并允许修改查询或重新搜索。

#### SRCH-02 全局 RAG 与会话创建

**故事**：作为用户，我希望系统从全局目录里找出相关论文和原文证据，并把它们保存成一次可继续使用的会话。

**规则**：

- 系统在全局论文目录中检索，召回与查询相关的论文和原文片段。
- V1.0 不设固定论文数量上限、不设固定证据数量上限，也不要求用户先选档位。
- 一次查询创建一个会话，保存查询、相关论文、证据和创建时间；会话属于发起用户。
- 检索成功后自动进入会话工作区；用户不需要再点一次“进入”。
- 没有相关证据时仍然创建空会话：显示“没有找到足够证据”，不生成四维，不允许对话，提供修改查询和浏览仓库的入口。
- 四维总结不阻塞会话创建；进入会话后按需生成。
- 会话保存后可以从主页最近会话重新打开；重新打开时使用当时的证据快照，不重新检索全局目录。

#### SRCH-03 会话工作区三视图

**故事**：作为用户，我希望在一个页面里切换对话、论文总结和相关仓库，不用在多个页面来回跳。

**规则**：

- 会话页顶部显示：本次查询、检索范围（全局目录）、相关论文数量、证据数量、相关仓库数量。
- 会话页有三个可切换视图：对话、论文总结、相关仓库。
- 首次进入默认打开“对话”；对话顶部用一条系统消息概述“找到了哪些论文”，并提示可以去“论文总结”查看四维。
- 切换视图不丢失当前输入、展开状态和对话内容。
- “对话”只使用本次会话的证据；“论文总结”展示本次会话涉及的论文；“相关仓库”展示与本次查询相关的公开仓库。
- 会话为空时，三个视图都显示空状态；对话输入不可用；提供“修改查询”“去仓库看看”入口。
- 会话页不提供筛选、排序设置和上传入口。


### 6.4 仓库

#### REPO-01 创建与设置仓库

**故事**：作为用户，我希望把自己的论文集合整理成仓库，并决定它是公开还是私有。

**规则**：

- 任意登录用户都可以创建仓库，填写名称、简介和可见性。
- 仓库归创建者所有；仓库名称在创建者范围内唯一。
- 公开仓库：所有登录用户可查看论文列表、可对话、可 star；只有创建者能编辑仓库和增删论文。
- 私有仓库：只有创建者和管理员能查看和对话；不出现在公开列表和推荐中；不能 star；普通用户不能读取。管理员可以管理私有仓库的信息、论文和对话，也可以删除。
- 创建者可以修改名称、简介和公开/私有状态，也可以删除仓库；管理员管理私有仓库时拥有同等管理能力。
- 公开转私有后，仓库和 star 不再展示、不参与推荐；已有 star 记录保留，转回公开时恢复展示。私有转公开后，管理员回到只读，编辑权归创建者。
- 删除仓库只删除集合、仓库对话和 star 关系，不删除全局目录中的论文。
- V1.0 不做仓库成员邀请和多人协作编辑。

#### REPO-02 从全局目录添加/移除论文

**故事**：作为仓库创建者（或管理私有仓库的管理员），我希望从全局目录挑选论文，而不是重新上传文件。

**规则**：

- 添加论文时搜索全局论文目录，选择一个或多个论文加入仓库。
- 只能添加已就绪的论文；处理中的论文不出现；已归档论文不能新加入。
- 重复添加同一篇论文时直接忽略，不产生重复记录。
- 创建者可以移除仓库中的论文；管理员管理私有仓库时也可以移除。移除只影响仓库集合，不删除全局论文。
- 移除后，仓库的新对话不再使用这篇论文；已有的历史消息保留，引用仍然可以打开全局论文详情。
- V1.0 不设仓库论文数量上限。
- 仓库为空时显示空状态，并提示创建者或管理员“添加论文”或“去全局搜索”。

#### REPO-03 仓库页面与论文列表

**故事**：作为用户，我希望打开仓库就能看到论文列表，并随时在旁边发起对话。

**规则**：

- 仓库页顶部显示：名称、简介、创建者、公开/私有标识、论文数量、star 数量（公开仓库）、star 按钮（符合条件时）、编辑入口（创建者；管理员对私有仓库显示管理入口）。
- 页面左侧是论文列表，一篇论文一行，不使用多列卡片或对比表。
- 每行展示标题、作者、年份、期刊/会议；可以展开四维总结；可以点击进入论文详情。
- 创建者可以添加论文、移除论文；管理员管理私有仓库时也可以；其他用户只能阅读和对话。
- 右侧默认收起；点击“对话”按钮后展开仓库对话面板。
- 仓库页不提供年份、期刊级别、论文类型筛选；V1.0 只通过左侧列表滚动浏览。
- 私有仓库对普通非创建者显示“无权访问”，不泄露名称、数量或论文信息；管理员可以进入管理。
- 公开仓库可以被其他登录用户打开、对话和 star；管理员对公开仓库仍然只读，不能编辑。

#### REPO-04 仓库对话与只读 Agent

**故事**：作为用户，我希望围绕整个仓库提问，让系统在仓库范围内查找证据并回答。

**规则**：

- 仓库对话的范围是整个当前仓库，仓库内所有论文都可以被检索；不固定只取某个子集。
- 对话可以使用仓库内的只读 Agent：它可以多步查找、比较和汇总，但只能在当前仓库内检索。
- Agent 不能访问全局目录、其他仓库、互联网或外部工具；不能新增、修改、删除任何数据。
- 回答中的事实性内容必须带引用；引用可以点击打开对应论文详情并定位原文。
- 仓库对话不显示“命中论文列表”，只显示回答和引用；论文列表始终在左侧。
- 找不到足够证据时明确拒答，并说明可以换一种问法或先向仓库添加论文。
- 空仓库不能发起对话，提示先添加论文。
- 公开仓库的对话只属于发起者，其他用户和仓库创建者看不到；私有仓库对话只有创建者和管理员可见。

#### REPO-05 Star 与相关仓库推荐

**故事**：作为用户，我希望通过 star 找到别人整理得好、又和当前方向相关的仓库。

**规则**：

- 只能 star 公开仓库；不能 star 自己的仓库；一个用户对一个仓库只能有一条 star，可以取消。
- star 是推荐信号，不是收藏夹；star 不会让用户获得额外权限。
- 私有仓库不能 star，不出现在推荐中；公开转私有后 star 隐藏，转回公开后恢复。
- 会话页的“相关仓库”展示公开仓库，排除自己的仓库，排除与本次查询无关的仓库。
- 相关性优先：仓库必须与本次查询、会话中的论文，或仓库标题/简介在主题上相关；star 只能加分，不能把高 star 的无关仓库推上来。
- 推荐卡片展示名称、创建者、简介、论文数量、star 数量和推荐理由。
- 没有相关仓库时显示空状态，并提供浏览公开仓库的入口。


### 6.5 论文总结与详情

#### VIEW-01 论文四维总结

**故事**：作为读者，我希望快速看懂一篇论文的问题、前人研究、方法和不足，并能回到原文核对。

**规则**：

- 四维固定为：问题、前人研究、方法/创新、不足。
- 四维是论文级总结：同一篇论文在会话、仓库、详情中看到的是同一份内容，不为每个用户或每个会话重复生成。
- 四维按需生成：用户第一次展开时生成，之后使用缓存；默认使用“标准”详略。
- 支持简要、标准、深入三种详略；切换时优先使用缓存，没有缓存再生成。
- 四维生成使用论文自身内容，不受本次会话证据范围的限制；这样不同场景看到的总结一致。
- 某一维信息不足时写“论文未明确说明”，不编造；可以附上来自同一篇论文的原文证据。
- 点击证据可以进入论文详情并定位原文；定位失败时至少打开论文详情，不伪造位置。
- 生成失败时显示失败状态和重试入口；不阻塞论文列表和其他论文的四维。
- 不做会话级四维；如果用户想比较整个领域，使用会话对话或仓库对话，而不是给会话生成一份四维。
- 归档论文已经生成的四维仍然可以查看；不因归档丢失历史内容。

#### VIEW-02 论文详情与下载

**故事**：作为读者，我希望在一页里看到论文信息、四维总结、原文和单篇对话入口。

**规则**：

- 详情页展示标题、作者、年份、期刊/会议、摘要、来源标识和四维总结。
- 所有登录用户都可以打开全局目录中的论文详情、查看四维、下载原文并发起单篇对话，不管它被放在公开仓库还是私有仓库。
- 有原文文件时提供下载；没有可下载文件时明确提示。
- 从会话、仓库或四维证据点击引用进入详情时，尽量定位到对应原文片段并高亮；无法定位时打开详情顶部并提示。
- 详情页提供“单篇论文对话”入口；对话只围绕这篇论文。
- 已归档论文显示“已归档”标识；旧会话、旧仓库仍可打开和引用。
- 详情页不提供上传、编辑元数据或加入仓库的入口；这些动作分别属于管理员和仓库创建者。

### 6.6 对话

#### QA-01 会话内对话

**故事**：作为用户，我希望围绕本次检索到的证据继续追问，而不是重新搜索整个目录。

**规则**：

- 会话对话只使用本次会话保存的论文和证据，不重新检索全局目录。
- 用户可以进行多轮追问；回答中的事实性内容必须带引用。
- 点击引用打开论文详情并定位原文；引用编号在同一回答内稳定。
- 找不到足够证据时明确拒答，不调用猜测，不编造来源。
- 会话没有证据时输入框不可用，并提示重新查询或去仓库。
- 用户问到本次会话之外的内容时，说明当前范围不够，并建议发起新的全局查询或去相关仓库。
- 回答可以逐步显示；生成中可以停止，停止后保留已经生成的内容并标记为已停止。
- 会话历史保存；重新打开会话时可以继续追问。
- 会话对话不做 Agent 多步检索，不扩大范围。

#### QA-02 单篇论文对话

**故事**：作为读者，我希望针对一篇论文深入提问，而不被其他论文干扰。

**规则**：

- 单篇对话只使用当前论文的内容，不访问全局目录、其他论文或仓库。
- 支持多轮追问；事实性内容带引用；点击引用定位到当前论文原文。
- 找不到证据时拒答，并提示可以换一种问法或查看四维总结。
- 对话历史按用户和论文保存；重新打开论文可以继续。
- 单篇对话不能把论文加入仓库，也不能触发全局搜索。

### 6.7 管理后台

#### ADM-01 管理总览与仓库管理

**故事**：作为管理员，我希望在一个后台看到系统概况并快速进入日常维护。

**规则**：

- 总览展示：论文总数、就绪论文数、处理中/失败数、仓库数（含私有）、用户数。
- 提供快捷入口：导入论文、论文目录、仓库管理、用户管理。
- 论文目录支持按标题搜索、查看状态、修正元数据、重试、归档。
- 用户管理支持创建、修改角色、停用、重置密码。
- 仓库管理支持查看所有仓库（含私有），进入私有仓库查看集合和对话、编辑信息、增删论文、删除仓库；公开仓库只读。
- 管理员对公开仓库只读；私有仓库的管理权限不延伸到公开仓库。
- 不做自动评测、审计日志、运营报表、部署和监控入口。


## 7 关键业务规则

### 7.1 全局目录与仓库分离

- 全局论文目录是唯一的论文来源；仓库只是论文的引用集合。
- 私有仓库对普通用户隐藏集合和对话，不隐藏论文；论文仍然可以在全局搜索、详情和单篇对话中出现。管理员因管理需要可以查看。
- 用户不能上传论文到仓库，也不能通过仓库绕过全局目录。

### 7.2 私有与公开

- 公开仓库：所有登录用户可见、可对话、可 star；只有创建者可编辑。
- 私有仓库：创建者和管理员可见、可对话；普通用户不可见；不能 star、不推荐。管理员可以管理私有仓库。
- star 只对公开仓库生效；公开转私有后隐藏，转回公开后恢复展示。
- 公开仓库的他人对话不向仓库创建者或其他用户展示；对话属于发起者。

### 7.3 三种对话范围

| 对话 | 检索范围 | 是否重新检索 | 是否用 Agent | 典型用途 |
| :--- | :--- | :--- | :--- | :--- |
| 会话对话 | 本次会话保存的论文和证据 | 不重新检索 | 否 | 围绕一次搜索结果追问 |
| 仓库对话 | 当前仓库的全部论文 | 可在仓库内多步检索 | 是，只读 | 仓库内比较、汇总、找证据 |
| 单篇对话 | 当前这一篇论文 | 只在这一篇内检索 | 否 | 精读一篇论文 |

三种对话不能互相越界：会话对话不能访问全局目录；仓库对话不能访问全局目录和其他仓库；单篇对话不能访问其他论文。

### 7.4 回答与引用

- 事实性回答必须带引用；引用要能打开对应论文并尽量定位原文。
- 没有足够证据时明确拒答，不编造论文、结论或引用。
- 引用定位失败时打开论文详情，不伪造高亮位置。
- 回答可以逐步显示，生成中可以停止；停止后保留已生成内容。

### 7.5 四维总结

- 四维是论文级共享内容，不是会话级内容。
- 四维在第一次展开时生成，之后缓存；同一篇论文在不同页面看到一致结果。
- 支持简要、标准、深入三种详略；默认标准。
- 四维使用论文自身内容，不受会话证据范围限制。
- 信息不足时明确写“论文未明确说明”。
- 不做用户级四维覆盖，不做会话级四维。

### 7.6 Star 与推荐

- star 是公开仓库的推荐信号，不是收藏夹。
- 一个用户对一个公开仓库最多一个 star，可取消；不能 star 自己的仓库。
- 相关仓库推荐必须先满足相关性，再参考 star；高 star 的无关仓库不能出现在推荐里。
- 私有仓库和用户自己的仓库不进入推荐。

### 7.7 不设数量限制

V1.0 的产品规则不包含：

- 全局论文数量上限；
- 仓库论文数量上限；
- 会话论文数量或证据数量上限；
- 每次回答的证据数量上限；
- 检索范围档位（如更聚焦/更全面）；
- 每轮检索次数上限。

系统按相关性和可用上下文组织结果；具体控制属于后续扩展，不作为本期 P0 的产品承诺。

## 8 范围外与后续扩展

### 8.1 本期不做

- 用户上传论文、仓库上传论文、PDF 入库；
- 年份、期刊级别、论文类型筛选；
- 仓库成员邀请、多人协作、评论、分享链接；
- 公开仓库的审核、举报和运营后台；
- 论文图谱、引用关系图、研究演化图；
- 图片内容识别、图片型 PDF/扫描件解析、Word 文档解析；
- 自动评测、指标看板、课程验收类评测；
- SSO、LDAP、TOTP、多因素认证、自注册；
- 审计日志、导出、移动端适配；
- 部署、容器化、监控、压测。

### 8.2 后续可扩展

- 检索范围档位和每轮证据数量控制；
- 仓库容量上限和配额；
- 年份、期刊级别、论文类型筛选；
- 推荐权重、排序策略和更多推荐信号；
- 仓库成员与协作；
- 自动评测和效果看板；
- SSO、LDAP、TOTP；
- 导出、分享和移动端。

## 9 典型场景

### 9.1 新生找方向

1. 用户在主页输入“LLM agents for scientific discovery”。
2. 系统从全局目录召回相关论文，自动进入会话。
3. 用户先在“论文总结”里逐行展开四维，快速判断哪些论文值得读。
4. 用户切到“对话”，问“这些工作主要分成哪几类？各自的局限是什么？”
5. 回答带引用；用户点引用进入详情，下载最相关的论文。
6. 用户在“相关仓库”里看到一个公开仓库，star 它，进入仓库继续看别人整理的论文集合。

### 9.2 组会准备

1. 用户打开自己的公开仓库，左侧是论文列表。
2. 用户点击“对话”，问“比较仓库里三篇论文的方法差异和实验设置。”
3. 仓库 Agent 在仓库内多步检索，给出对比和引用。
4. 用户点引用回到原文核对，把有争议的论文加入自己的私有仓库继续精读。

### 9.3 单篇精读

1. 用户从会话点进一篇论文详情。
2. 查看四维总结，展开“不足”这一维，点证据定位原文。
3. 下载 PDF，并在单篇对话里问“这篇论文的方法在什么条件下会失效？”
4. 回答只使用这篇论文的内容，没有证据时明确拒答。

### 9.4 管理员导入

1. 管理员进入后台，上传一批 PDF。
2. 查看每篇的处理状态；失败的论文重试。
3. 修正一篇论文的标题和年份。
4. 论文进入全局目录，用户在主页可以搜索到。
5. 管理员创建一个新用户账号，并设置角色。

## 10 一句话记住

**全局目录负责“有什么论文”，仓库负责“我挑了哪些论文”，会话负责“这次找到什么”，四维负责“这篇论文讲什么”，三种对话负责“在哪个范围内问”。**
