## 1. 项目是什么，边界在哪

**一句话**：PaperLens 是给研究组用的论文知识库问答平台——管理员把 PDF 导入全局目录，
普通用户做全局检索并围绕检索结果对话，把自己的论文整理成仓库，仓库内可再对话。

**角色**：只有 `reader`（普通用户）和 `admin`（管理员）。账号由管理员创建，**没有自注册**
（`POST /auth/register` 已删除，访问返回 404）。

**三种对话范围**（互相隔离，不能越界）：

| scope | 检索范围 | 谁看得到对话 |
| --- | --- | --- |
| `session` | 创建会话时保存的论文与证据快照 | 只有会话所有者，管理员也看不到 |
| `repo` | 当前仓库内的论文（D4 实现） | 公开仓库只有发起者；私有仓库创建者/管理员可见全部 |
| `paper` | 当前这一篇论文 | 只有发起者 |

**本期明确不做**（看到这些需求先停下确认，不要“顺手实现”）：

- 用户上传论文、仓库成员邀请/协作、分享链接；
- 年份/期刊/类型筛选、图谱、图片理解、OCR、Word 解析；
- 公开仓库审核、用户删除、取消归档、物理删除论文、会话删除、消息编辑/重新生成；
- Docker/部署、SSO/LDAP/TOTP、审计日志、评测平台。

**P0 不设数量上限**：论文数、仓库数、证据数、每轮 chunk 数都不写成产品限制。
代码里的 8 篇/20 条/12 条引用是**内部预算**（契约 §1.14），50 页是 PDF 查询的接口输入限制。
这些都不要写进用户故事文档，也不要拿来拒绝用户请求。

## 5. 数据模型与迁移

| 表 | 作用 | 关键约束 |

## 6. 必须遵守的业务不变量

这些规则已经有测试保护，改代码时不要“优化掉”。违反其中任何一条，验收都会失败。

### 6.1 可见性

1. **全局目录**只返回 `status=ready` 且 `is_archived=false` 的论文；这个条件的唯一来源是
   `app/services/paper_queries.py::visible_paper_conditions()`。D4 的搜索/推荐不要另写一份。
2. 论文**详情/下载/单篇对话**对已归档论文仍可用（详情返回 `is_archived=true`）；
   归档只影响“新检索/新加入仓库”，不影响历史会话、消息、引用。
3. 私有仓库对无权限用户统一 **404 `repo_not_found`**，不能泄露名称、数量、论文或对话存在性。
4. 公开仓库的他人对话：创建者/普通用户 → 404 `conversation_not_found`；
   管理员（非创建者、非发起者）→ 403 `forbidden`。这是契约里唯一按角色区分的“泄露 vs 拒绝”。

### 6.2 会话快照

5. 会话保存的是**当时的论文与证据**：`session_papers`（paper_id + rank）与
   `session_evidence`（chunk_id、page、quote、rank）。之后新增/归档论文不改变旧会话；
   详情里的标题/作者等元数据取**当前值**。
6. 查询预算（内部，不是产品限制）：最多 **8 篇论文、20 条证据**；正文 FULLTEXT 无命中时用
   标题/摘要命中，并取命中论文**前 2 个 chunk**作为证据；quote 截到 **500** 字符。
7. 检索词长度 ≥2 用 MySQL ngram FULLTEXT；单字符回退 `LIKE`，且必须转义 `\`、`%`、`_`。
   这个回退在 D2/D3 都有，D4 的仓库检索要沿用。

### 6.3 对话与引用

8. 每个用户在每个范围**只有一条对话**：`(user_id, scope_type, scope_id)` 唯一。
   仓库对话复用 `conversations` 表，`scope_type='repo'`，`scope_id=repo_id`。
9. 请求体只有 `message`（1–2000，去空白后非空）；多传字段 422（`extra="forbid"`）。
   范围只由 URL 决定，模型看不到 `repo_id/session_id`（工具用闭包绑定）。
10. SSE 事件顺序：`meta` → `citation`（0..N 条）→ `token`（可多条）→ `done`；
    流开始前的错误返回普通 JSON，流开始后的错误发 `event: error`。
    心跳是每 15 秒的注释行 `: ping`。
11. **回答先完整缓冲，再校验引用，最后才发 token**（契约 §11.1.1 第 8 条）。
    不得边生成边发未校验文本。
12. 引用校验：`[n]` 必须落在证据编号内；`quote` 必须是 chunk 的真实子串；
    最多 **12** 条；无效引用丢弃后**重新连续编号并同步改写正文**；
    没有任何有效引用时用同一提示重试一次；仍失败就用固定拒答文案
    `根据当前资料，没有足够证据回答这个问题。`
13. 落库规则：流开始并写完用户消息后，助手消息在完成/停止/错误时写入
    （`complete/stopped/error`）；流前 JSON 错误不写任何消息、不创建新对话。
    客户端断开时尽力保存已生成内容（`stopped`）。

### 6.4 仓库（D4 要落地的部分）

14. 仓库只引用全局论文，不复制、不上传；添加只接受 `ready` 且未归档；
    已在仓库中的论文重复添加忽略；`ignored.reason` 判定顺序：
    `not_found → duplicate → not_ready → archived`。
15. 仓库论文列表**包含已归档但在仓库中的论文**（`is_archived=true`），
    所以**不能**直接用 `visible_paper_conditions()` 过滤仓库列表。
16. Star：只能 star 公开仓库，不能 star 自己的；私有仓库 `star_count=0`、`is_starred=false`；
    公开转私有后 star 记录保留但不展示/不参与推荐，转回公开恢复。
17. `updated_at` 只在仓库元数据变更、论文加入/移除时更新；Star 和对话不更新。
18. 删除仓库只删仓库、关系、star，以及该仓库的对话与消息，**不删全局论文**。
19. 管理员对**公开**仓库只读（除非自己是创建者）；对**私有**仓库有完整管理权，
    可看全部对话、可删仓库、可发起对话。
20. 权限计算只写一处（建议 `repo_permissions(repo, user)`），接口和序列化都调用它，
    不要在每个 endpoint 里重复 if/else。

### 6.5 全局约定

21. 错误响应固定 `{"error": {"code", "message", "details"}}`，`details` 始终存在（可为 null）。
    新增错误码先查 API 文档 §15，不要自造。
22. 时间输出 `YYYY-MM-DDTHH:MM:SSZ`；库里存 naive UTC（`app.core.time.utcnow`）。
23. 列表分页 `page/page_size`（page_size ≤100，超页返回 200 + 空数组）；
    消息分页用 `limit/before_id`，**items 按 id DESC（最新在前）**，前端自己反转。
24. 用户可见文案用中文；错误 `code` 用英文 snake_case。

## 9. 已知陷阱（都是实际踩过的，别重踩）

### 9.1 MySQL 迁移

1. **downgrade 不要 `drop_index` 再 `drop_table`**。MySQL 在删除被外键使用的索引时报
   `1553 Cannot drop index ... needed in a foreign key constraint`。D2/D3 的写法是
   `op.drop_table(...)` 按依赖反序，让 MySQL 自己处理；`0004` 的 downgrade 就是手写的。
2. 建模时给外键列单独加 `index=True`，否则 MySQL 会自动建索引，名字和 Alembic 预期不一致，
   后续 `drop_index` 会找不到名字。
3. `alembic revision --autogenerate` 对 MySQL 的 FULLTEXT / `WITH PARSER ngram` 支持不完整：
   `0003` 是手写的。D4 没有 FULLTEXT，正常生成后检查索引名与 `ondelete` 即可。
4. `alembic check` 必须干净；如果它报“new upgrade operations”，说明模型改了但迁移没跟上。

### 9.2 测试

5. **不要用 `TRUNCATE` 清表**：带 FULLTEXT 的表在本机 TRUNCATE 极慢（曾约 5 分钟），
   现在统一用 `DELETE`（`tests/api/conftest.py`）。
6. 清表后必须 `ALTER TABLE users AUTO_INCREMENT = 1`：D1 的旧测试按 `/admin/users/1` 访问。
7. `httpx` 在 `files={"file": ("", b"...", "application/pdf")}` 时会把空文件名当成普通表单字段，
   请求体不是 multipart，接口会在进入函数前 422。测试空白文件名要用 `"   .pdf"` 这类值，
   服务端已用 `safe_basename`/`_pdf_display_name` 归一化。
8. 测试是**串行**的；跑全量时不要再开第二个 pytest，也不要在测试运行时手工 `alembic upgrade`。

### 9.3 SSE 与引用

9. `RequestContextMiddleware` 必须是纯 ASGI（D1 已改）。用 `BaseHTTPMiddleware` 会缓冲 SSE，
   表现为前端“一次性收到全部内容”或超时才收到。
10. 引用校验必须在发 `token` 之前；D3 的实现是 `collect_stream()` 收完整答案再校验，
    再按 32 字符切块发 `token`。不要改成边流边发。
11. 客户端断开在 ASGI 层表现为 `CancelledError` / `GeneratorExit`，已生成内容挂在异常的
    `partial` 属性上；保存 `stopped` 消息要用独立 session（`_persist_quietly`），
    不能复用已被取消的请求 session。
12. 心跳是注释行，不算事件；前端解析时忽略以 `:` 开头的行。
13. 停止路径的测试不要只断言 HTTP 流：D3 直接驱动 `_chat_events()`，取消后轮询数据库等
    `status=stopped`（后台任务落库），参考 `test_session_chat_stop_saves_stopped`。

### 9.4 检索

14. MySQL ngram 默认 token 是 2，单字搜不到；所有全文检索入口都要有单字符 `LIKE` 回退，
    并转义 `\`、`%`、`_`（`_escape_like`）。
15. FULLTEXT 索引只建在 `paper_chunks.content` 与 `papers.title/abstract` 上；
    搜索必须 join `papers` 并加 `visible_paper_conditions()`，否则会搜到归档/未就绪论文。
16. `search_catalog()` 在没有正文命中时会用标题/摘要命中，并为每篇取前 2 个 chunk；
    这条路径的 `score=0.0`、`quote` 从开头截取，不要误认为是 bug。

### 9.5 路由与契约

17. `GET /repos/related` 与 `GET /repos/{repo_id}` 同前缀：**必须把 `related` 注册在
    `/{repo_id}` 之前**。把 `repo_id` 声明为 `Path(ge=1)` 的 int 只能把误匹配变成 422，
    仍无法访问推荐接口。契约 §3 特意提醒过这一点。
18. 批量添加论文成功返回 **200**，不是 201；删除论文/取消 star 是 **204/200 幂等**，
    不要因为“创建了关系”就返回 201。
19. `PATCH` 空对象要 400，字段显式为 `null` 要 422（参考 `AdminPaperUpdate` 的 validator 写法）。
20. 请求模型统一 `model_config = ConfigDict(extra="forbid")`；否则未知字段被静默忽略，
    与契约“多传字段 422”不符。
21. 分页越界返回 200 + 空数组；资源不存在才是 404。

### 10.2 迁移与模型（`0005_repos`）

> **重要**：API 文档 §16.1 把 `0005_repos` 的前置写成 `0003_papers`（因为仓库只依赖论文），
> 但本仓库的迁移链已经到 `0004_sessions_chat`。实际生成时 **`down_revision` 必须是
> `0004_sessions_chat`**，保持单头线性；否则会出现两个 head，`alembic upgrade head` 报错。
> 这是契约表与仓库现状的已知差异，不需要改契约。

建议结构（字段名尽量与契约一致）：

```text
repos
  id            BIGINT PK
  owner_id      BIGINT FK users.id ON DELETE CASCADE, index
  name          VARCHAR(64)  NOT NULL
  description   VARCHAR(500) NOT NULL DEFAULT ''
  visibility    VARCHAR(16)  NOT NULL DEFAULT 'private'   # public/private
  created_at    DATETIME NOT NULL
  updated_at    DATETIME NOT NULL
  UNIQUE (owner_id, name)          # 依赖 utf8mb4_0900_ai_ci 实现不区分大小写
  INDEX (owner_id, updated_at)     # scope=mine 列表

repo_papers
  id            BIGINT PK
  repo_id       BIGINT FK repos.id ON DELETE CASCADE, index
  paper_id      BIGINT FK papers.id ON DELETE CASCADE, index
  added_at      DATETIME NOT NULL
  UNIQUE (repo_id, paper_id)

repo_stars
  id            BIGINT PK
  repo_id       BIGINT FK repos.id ON DELETE CASCADE, index
  user_id       BIGINT FK users.id ON DELETE CASCADE, index
  created_at    DATETIME NOT NULL
  UNIQUE (repo_id, user_id)
```

- **不要**建成员表、邀请表、公开审核表；V1.0 没有这些概念。
- 名称唯一性依赖数据库排序规则；如果要显式保证，可在服务层先 `select` 一次并返回 409，
  但仍保留唯一约束兜底（并发下捕获 `IntegrityError` 转 409）。
- 删除仓库时，`conversations` 的 `(scope_type='repo', scope_id)` 没有外键，需在服务层显式删除
  对应对话与消息（或迁移时不要加约束，靠事务删除）。别让仓库删除后留下孤儿对话。
- `updated_at` 用 `onupdate=utcnow` 不够：Star/对话也会改仓库行以外的数据，但**不能**改仓库
  `updated_at`；而加/删论文要显式 `repo.updated_at = utcnow()`。**不要**把 `updated_at`
  放在 `repo_papers` 的触发器式逻辑里。

### 10.3 服务层设计（建议新建 `app/services/repos.py`）

**单一权限函数**（每格都要和 API 文档 §10.4.1 一致）：

```python
def repo_permissions(repo, user) -> RepoPermissions:
    is_owner = repo.owner_id == user.id
    is_admin = user.role == UserRole.admin.value
    is_public = repo.visibility == RepoVisibility.public.value
    can_manage = is_owner or (is_admin and not is_public)
    return RepoPermissions(
        can_edit=can_manage,
        can_delete=can_manage,
        can_manage_papers=can_manage,
        can_star=is_public and not is_owner,
        can_chat=True,          # 空仓库也是 True；对话时再返回 409
    )
```

| 用户 / 仓库 | can_edit | can_delete | can_manage_papers | can_star | can_chat |
| --- | :---: | :---: | :---: | :---: | :---: |
| 创建者（公开/私有） | true | true | true | false | true |
| 其他普通用户（公开） | false | false | false | true | true |
| 管理员（公开，非创建者） | false | false | false | true | true |
| 管理员（私有，非创建者） | true | true | true | false | true |
| 其他用户（私有） | 404 | 404 | 404 | 404 | 404 |

建议函数：

| 函数 | 职责 |
| --- | --- |
| `get_visible_repo(db, repo_id, user)` | 公开所有人；私有仅创建者/管理员；否则 404 `repo_not_found` |
| `require_repo_manager(repo, user)` | 创建者，或管理员且私有；否则 403 `forbidden` |
| `repo_summary_rows(db, repos, user)` | 批量算 `paper_count`/`star_count`/`is_starred`，避免 N+1 |
| `get_repo_detail(db, repo, user)` | summary + permissions；权限按**变更后**状态计算 |
| `list_repos(db, user, scope, page, page_size)` | `mine` = owner_id；`public` = visibility=public；`updated_at DESC, id DESC` |
| `create_repo / update_repo / delete_repo` | 重名 409；空 PATCH 400；删除时清理仓库对话 |
| `add_papers(db, repo, paper_ids)` | 去重保序；added/ignored；有新增才刷新 `updated_at` |
| `remove_paper(db, repo, paper_id)` | 幂等；实际删除才刷新 `updated_at` |
| `set_star(db, repo, user, starred)` | 幂等；返回 `{starred, star_count}` |
| `list_repo_papers(db, repo, page, page_size)` | 含归档；`added_at DESC, paper_id DESC`，返回 `PaperBrief`（含 `is_archived`） |

统计口径（容易写错）：

- `paper_count` = `repo_papers` 行数，**包含已归档论文**。
- `star_count` = `repo_stars` 行数，**不过滤停用用户**；私有仓库强制返回 0。
- `is_starred` = 当前用户在 `repo_stars` 是否有行；自己的仓库与私有仓库强制 false。
- `paper_count`/`star_count` 用聚合子查询或一次 group by 批量取，不要在循环里查。
- `owner` 一律用 `UserBrief`（只有 `id`、`display_name`，**不含邮箱**，契约 §2.2）；
  只有后台仓库列表额外返回 `owner_email`（契约 §12.1）。

添加论文的判定顺序（必须严格）：

```text
for paper_id in 去重后的请求顺序:
  论文不存在                    → ignored: not_found
  已在 repo_papers              → ignored: duplicate
  status != ready               → ignored: not_ready
  is_archived == true           → ignored: archived
  否则                           → added（写关系，added_at=now）
```

`added` 与 `ignored` 都按请求首次出现顺序返回；全部 ignored 时不刷新 `updated_at`；
`paper_ids` 为空数组 → 422；单次最多 100 个，全部重复时仍返回 200 + `ignored`。

Star 的判定顺序（先可见性，再可见性细分）：

```text
仓库不可见（不存在 / 他人私有） → 404 repo_not_found
visibility == private          → 400 repo_not_public
repo.owner_id == user.id       → 400 cannot_star_own_repo
否则插入/删除 repo_stars，返回 200 {starred, star_count}
```

### 10.4 相关仓库（`GET /repos/related`）

契约要求“相关性优先，Star 只加分”。推荐实现：

1. `session_id` 必须属于当前用户，否则 404 `session_not_found`。
2. `session.has_evidence == false` → 直接返回空页（`total=0`），不要退回“最热仓库”。
3. 关键词来源：`session.query` + `session_papers` 对应论文的 `title/abstract`。
   中文没有分词依赖，建议按标点/空白切分，再对中文片段取 2–4 字 n-gram，去停用词，限制词数。
4. 候选：`visibility='public'` 且 `owner_id != current_user.id`。
5. 打分：仓库名命中权重 3、简介 2、仓库内论文标题 1；归一化到 0–1；
   只保留 base_score > 0 的仓库；再加 `0.2 * ln(1 + star_count)` 的小幅加分。
6. 排序：`score DESC, star_count DESC, id ASC`；`total` 为满足条件的总数。
7. `reason`：中文、非空、≤100 字，必须说明相关性（命中了哪些词/几篇相关论文），
   不能只写“热门”。
8. 性能：先按名称/简介/论文标题做关键词预筛（LIKE 或 FULLTEXT），再对候选打分；
   不要对全库每个仓库都加载全部论文。课程规模下也避免 N+1。
9. `SessionDetail.related_repo_count` 复用同一套过滤与计数（不分页），别写第二套规则。

### 10.5 仓库对话与只读 Agent（`POST /repos/{id}/chat/stream`）

**前置校验（流前，返回 JSON 错误）**：

```text
仓库不可见                                  → 404 repo_not_found
repo_papers 为空                            → 409 repo_empty
有论文但没有任何 chunk（数据异常）           → 409 repo_empty
未配置模型                                  → 503 llm_unavailable（get_llm_client() 抛出）
```

**对话与消息**：复用 `get_or_create_conversation(scope=ChatScope.repo, scope_id=repo_id)`；
用户消息在流开始写库；助手消息按完成/停止/错误落库（§6.3）。**不要**新建对话表。
会话对话在创建时会写一条 `system` 快照消息；仓库/单篇对话不写 system 消息，
但 `conversation.message_count` 统计时要包含可能存在的 system 消息（契约 §10.14）。

**证据范围**：`repo_papers` join `papers`，**包含已归档但仍在该仓库的论文**，
不包含已移除论文；不要套 `visible_paper_conditions()`（它会排除归档）。

**只读 Agent**（契约 §11.3：最多 5 步，只能读当前仓库）：

- 用 `app/core/ai/tools.py` 的 `ToolRegistry`，只注册一个 `search_repo` 工具，
  参数只允许 `query`、`limit`；`repo_id` 由闭包绑定，**不能**出现在模型可见参数里。
- 工具内部查询必须同时限制 `repo_id` 与 `paper_id ∈ repo_papers`，只返回
  `paper_id/chunk_id/page/quote/title`，不返回写操作。
- 推荐流程：`run_tool_loop(client, messages, registry, max_steps=min(settings.llm_max_tool_steps, 5))`
  收集证据 → 再追加“现在基于以上证据给出最终回答” → `collect_stream()` 得到完整答案 →
  `validate_answer_citations()` → 发 `citation`/`token`。
  （`LLM_MAX_TOOL_STEPS` 默认 4；契约上限 5，不要把 5 写死。）
- 证据编号要在工具结果里稳定分配；把用过的 `ChatEvidence` 收进一个列表，
  最终校验只在这个列表内做（跨仓库/不存在的 chunk 一律丢弃）。
- `run_tool_loop` 抛 `tool_loop_exceeded`（504）时，如果已经发过 `meta`，就发
  `event: error`；如果还没开始流，就直接抛 `AppError` 返回 JSON。两种都符合契约，
  **在完成报告里写清楚你选了哪种**。
- 不要给模型任何“新增/修改/删除/跨仓库/联网”的工具。

**SSE 复用**：`_chat_events()` 现在定义在 `app/api/v1/endpoints/sessions.py`，
`papers.py` 已经跨模块 import 它。D4 建议把它（连同 `_persist_quietly`）**原样移到**
`app/services/chat_stream.py`，三个入口共用；移动后必须重跑 D3 的 20 个 chat 测试。
如果不想动，就 import 复用，但不要再复制一份。

**模型调用边界**：流前只做 `get_llm_client()`（可能 503）；真正的模型调用放进生成器，
这样断线能被 `CancelledError` 捕获并保存 `stopped`。

**空仓库的权限语义**：`RepoPermissions.can_chat` 仍为 true；只有调用对话接口才 409。
