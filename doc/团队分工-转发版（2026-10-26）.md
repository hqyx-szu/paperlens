# PaperLens 项目说明与分工（简单版）

> 周期：2026-10-26 — 2026-11-01，共 7 天
> 方式：每个人在自己电脑上开发，不用 Docker
> 当前进度：登录功能已经做好，其他功能还没开始

---

## 一、这个项目是什么

**PaperLens 是一个“论文版”的搜索 + 聊天 + 收藏网站。**

管理员先把论文 PDF 放进系统，普通用户就可以：

- **搜论文**：输入一句话，比如“大模型怎么做科研”，系统找出相关论文；
- **问论文**：直接对这些论文提问，回答会标明“这句话来自哪篇论文”；
- **看总结**：每篇论文自动总结成四块——问题、前人研究、方法/创新、不足；
- **收论文**：把喜欢的论文整理成自己的“仓库”，像歌单一样，可以公开也可以私有；
- **逛别人的仓库**：看到别人整理得好的公开仓库，可以 Star。

一句话记住：

> **管理员负责“有什么论文”，用户负责“搜论文、问论文、收藏论文”。**

## 二、需要完成哪些功能

### 普通用户能看到的功能

| 功能 | 用户看到什么 |
| --- | --- |
| 登录 | 用邮箱和密码登录，没有注册入口，账号由管理员创建 |
| 搜论文 | 主页输入关键词，或者上传一个 PDF 当例子 |
| 会话页 | 搜完自动进入，有三个标签：对话、论文总结、相关仓库 |
| 论文对话 | 回答一个字一个字出现，带 [1][2] 引用，点引用打开论文 |
| 四维总结 | 每篇论文显示：问题、前人研究、方法/创新、不足 |
| 论文详情 | 标题、作者、年份、摘要、四维、下载 PDF |
| 单篇对话 | 只针对当前这一篇论文提问 |
| 仓库 | 新建仓库、从论文库添加论文、公开或私有 |
| 仓库对话 | 在仓库里提问，系统会自己查几次再回答 |
| Star | 给别人的公开仓库点赞，会话页能看到相关仓库 |

### 管理员能用的功能

| 功能 | 管理员看到什么 |
| --- | --- |
| 用户管理 | 创建用户、改角色、停用、重置密码 |
| 论文目录 | 上传 PDF、看解析状态、失败重试、改标题作者、归档 |
| 管理总览 | 论文数、处理中、失败数、仓库数、用户数 |
| 仓库管理 | 查看所有仓库；私有仓库可以编辑和删除，公开仓库只能看 |

### 本周必须做出来的（演示主线）

```text
管理员登录 → 建用户 → 上传 PDF → 解析成功
→ 用户登录 → 搜索 → 进入会话 → 流式问答带引用
→ 展开四维 → 看详情、下载 → 单篇提问
→ 建仓库、加论文 → 仓库 Agent 回答
→ Star、看相关仓库 → 管理员看总览
```

### 时间不够可以先简化的

- 上传 PDF 当搜索条件（先只做文字搜索）；
- 四维的“深入”档（先做简要和标准）；
- 相关仓库推荐（先用关键词匹配，不做复杂算法）；
- 管理后台编辑私有仓库的论文（先做查看和删除）。

## 四、每个人具体做什么

### PM：项目经理

**不写业务功能，负责让六个人能一起干活、最后能交东西。**

- 第一天建 Git 仓库，分好分支和任务；
- 每天 09:30 开 15 分钟站会，问清楚谁卡住了；
- 每天中午和晚上把大家的代码合到一起，保证能运行；
- 周五按清单完整点一遍演示流程，记下哪里不通；
- 周六组织改 bug，周日收 6 份报告、打包代码、提交。

**做完的效果**：最后有一个能运行的完整项目，6 份报告交齐。

**报告写**：怎么排任务、怎么合并代码、怎么验收。

---

### D1：登录、权限、管理后台、AI 公共代码

**负责“门”和“公共插座”。**

- 做登录页和登录接口；
- 给用户分两种角色：普通用户、管理员；
- 做管理员创建用户、停用用户、重置密码；
- 保证普通用户打不开管理后台；
- 写一套“调用 AI”的公共代码，其他四个人都来用，不用各自重复写；
- 做管理后台首页和用户管理页。

**做完的效果**：管理员能建一个普通用户；普通用户登录后打开 `/admin`，显示“无权访问”。

**报告写**：AI 怎么调用、回答怎么一个字一个字出现、权限怎么拦。

---

### D2：论文上传和解析

**负责“论文怎么进系统”。**

- 做管理后台的「论文目录」页；
- 管理员可以一次上传多个 PDF；
- 系统自动从 PDF 里提取文字；
- 自动识别标题、作者、年份、期刊、摘要；
- 把正文切成一段一段，方便后面搜索；
- 解析失败显示原因，可以点重试；
- 论文可以归档，归档后不再出现在新搜索里。

**做完的效果**：上传 3 篇 PDF，状态从“解析中”变成“就绪”，搜索时能搜到里面的句子。

**报告写**：PDF 怎么解析、状态怎么变化、失败怎么处理。

---

### D3：搜索、会话、聊天

**负责“用户搜到论文之后的一切”。**

- 做主页搜索框和搜索结果；
- 搜索后自动创建一次“会话”，把结果保存下来，以后打开不用重新搜；
- 做会话页的三个标签：对话、论文总结、相关仓库；
- 做会话里的问答：回答一个字一个字出现，带引用；
- 没有找到证据时，明确说“没有足够证据”，不编造；
- 做单篇论文的问答，只能聊这一篇；
- 点引用可以打开对应的论文。

**做完的效果**：输入“LLM agent” → 出现 5 篇论文 → 问“它们有什么区别” → 回答逐字出现并带 [1][2] → 点 [1] 打开论文。

**报告写**：怎么搜索、会话怎么保存、流式回答和引用怎么做。

---

### D4：仓库、Star、仓库 Agent

**负责“把论文整理成自己的收藏”，以及会自己查资料的 Agent。**

- 做仓库页：论文列表、右侧对话面板；
- 用户可以新建仓库，填名称、简介、公开或私有；
- 从论文库里搜索并添加论文，也可以移除；
- 公开仓库所有人能看，只有创建者能改；私有仓库只有自己和管理员能看；
- 做 Star：只能 Star 别人的公开仓库；
- 做“相关仓库”：在会话页推荐和这次搜索有关的公开仓库；
- 做仓库问答：系统先在仓库里查几次，再比较、总结，回答带引用，而且只能看不能改。

**做完的效果**：建一个“我的 RAG 仓库”，加 3 篇论文，问“比较这三篇的方法”，系统先查两次再回答，带 3 个引用。

**报告写**：Agent 怎么只在仓库里工作、怎么多步查资料、怎么保证不改数据。

---

### D5：前端页面、四维总结、论文详情

**负责“整个网站长什么样”，以及四维总结。**

- 搭好前端框架：顶部导航、页面切换、登录检查、统一报错；
- 做论文详情页：标题、作者、摘要、下载、单篇对话入口；
- 做四维总结：第一次展开时生成，第二次直接读缓存；
- 四维分简要、标准、深入三档；
- 提供公共页面组件，其他四个人写自己的页面时直接套用。

**做完的效果**：打开一篇论文 → 点“展开四维” → 显示问题、前人研究、方法/创新、不足 → 收起来再点，秒开。

**报告写**：前端怎么用 AI 生成、四维怎么生成和缓存。

## 五、怎么保证六个人不重复

1. **一个页面只有一个负责人**
   - 登录 / 管理后台用户 = D1
   - 管理后台论文 = D2
   - 主页 / 会话 = D3
   - 仓库 = D4
   - 论文详情 / 四维 = D5

2. **一类数据只有一个负责人**
   - 用户 = D1
   - 论文 = D2
   - 会话和消息 = D3
   - 仓库和 Star = D4
   - 四维总结 = D5

3. **调 AI 的公共代码只有 D1 写**
   - D2、D3、D4、D5 都调用 D1 的代码；
   - 各人只写自己功能里的提示词，不重复写“怎么连 AI”。

4. **接口先商量再改**
   - 谁要改接口，先在群里说；
   - PM 负责记录，避免前后端对不上。

## 八、附：四维是什么

四维就是每篇论文固定总结的四个角度：

| 四维 | 回答的问题 | 例子（一篇“用大模型做科研”的论文） |
| --- | --- | --- |
| **问题** | 它想解决什么？ | 科研太慢，想让大模型帮忙 |
| **前人研究** | 别人之前怎么做的？ | 以前用规则系统，只能做单一任务 |
| **方法/创新** | 它怎么做的？新在哪？ | 把读文献、提假设、写代码串成一个自动流程 |
| **不足** | 它哪里不行？ | 只验证了两个学科；会编造引用；成本高 |

三条规则：

- 四维是**论文**的总结，不是某次搜索的总结；
- 第一次展开才生成，之后读缓存；
- 信息不够就写“论文未明确说明”，不许编。
