### 关键实现决策

- **权限唯一实现**：`repo_permissions(repo, user)`，`can_manage = is_owner or (admin and private)`；
  endpoint、详情序列化都只调它，无第二份 if/else。
- **统计防扇出**：`repo_papers` 与 `repo_stars` 分别 `group by repo_id`，再与“我的 star 集合”在 Python
  合并；不做双 outer join（会笛卡尔积放大计数）。私有仓库 `star_count` 强制 0、`is_starred` 强制 false。
- **重名**：服务层预检 + `IntegrityError` 兜底转 409；库排序规则 `utf8mb4_0900_ai_ci` 保证大小写不敏感。
  改名时用 `Repo.id != 当前仓库` 排除自身，因此改大小写不算冲突。
- **`updated_at`**：PATCH 成功即显式 `utcnow()`（值未变也刷新），不依赖 `onupdate`，避免 Star/对话误刷新。
- **删除级联**：先 `DELETE conversations WHERE scope_type='repo' AND scope_id=?`（messages 由 0004 的
  FK 级联），再删仓库（`repo_papers`/`repo_stars` 由 FK 带走）；论文不受影响。

## S2 仓库论文（接口 36–38）

**交付**：`app/schemas/repo.py` 增加 `IgnoredPaper` / `RepoPaperAddRequest` / `RepoPaperAddResult`；

**关键决策**

- 列表**不套** `visible_paper_conditions()`：已归档但仍在仓库的论文必须出现（`is_archived=true`），
  排序 `added_at DESC, paper_id DESC`，`total` 含归档。
- 添加：去重保序 → 判定顺序严格为 `not_found → duplicate → not_ready → archived`；
  `added`/`ignored` 都按请求首次出现顺序；**200** 而非 201；全部 ignored 不刷新 `updated_at`。
- 边界按契约与交接：`paper_ids` 原始数组 1–100、元素 ≥1，否则 422；**全部重复/不合格仍是 200 + ignored**
  （评审提出的“全重复 422”不成立：去重保留首次出现，永不为空）。
- 移除幂等：不存在也 204；只有真实删除才刷新 `updated_at`；不删全局论文。

**验证**：`pytest -q tests/api/test_repo_papers.py` → 15 passed。

## S4 相关仓库（接口 41）+ `related_repo_count` 接回

**交付**：`app/services/repo_related.py`（关键词抽取 + 纯函数打分 + 候选预筛 + 排序/分页/理由）、
`RelatedRepoItem`/`RelatedRepoPage`、`GET /repos/related`（注册在 `/{repo_id}` 之前）、
`session_service.get_session_detail()` 改为调用 `count_related_repos`；`tests/api/test_repo_related.py`（8 组）。

**关键决策**

- 打分公式按契约 §10.12 与交接 §10.4：仓库名 3、简介 2、仓库论文标题 1（归一化），
  `+0.2*log(1+star_count)`；**只保留 base>0**，因此无关高 star 仓库无法靠 star 入选。
  评审建议的 0.6/0.3/0.1 未采纳（与契约/交接不一致）。
- 关键词：查询词 + 会话论文标题/摘要；中文 2–4 字 n-gram、英文小写分词、去停用词、上限 20。
- 候选预筛：名称/简介 LIKE + 仓库论文标题 LIKE（转义 `%`/`_`/`\`），只对候选加载论文标题，
  避免全库 N+1；`paper_count`/`star_count` 复用批量统计。
- `has_evidence=false` → 空页 `total=0`，不回退“最热”；排除自己与私有。
- `related_repo_count` 复用同一 `rank_related_repos`，不改 `sessions.py` 调用签名。

**验证**：`pytest -q tests/api/test_repo_related.py` → 8 passed；`test_sessions.py`/`test_search.py` 原有
`related_repo_count == 0` 断言（无仓库场景）仍通过。

## S5 仓库对话只读 Agent（42–43）

**交付**：`app/services/chat_stream.py`（`_chat_events` + `_persist_quietly` 原样搬迁并拆成
`meta_event` / `answer_events` / `chat_events`）、`app/services/repo_chat.py`（提示词、只读工具
`search_repo`、工具循环、最终回答）、两个路由；`sessions.py` / `papers.py` / `test_chat.py` 同步 import；
`tests/api/test_repo_chat.py`（13 组）。

**关键决策**

- 生成器分层：`meta` → 工具循环 → 缓冲答案 + 引用校验 → `citation`/`token`/`done`；
  D3 的 `chat_events()` 行为完全不变（D3 的 20 个 chat 测试与 sessions/search/papers 共 69 项回归通过）。
- 工具超限（504）：**`meta` 之后发 `event: error`**（用户消息已落库），完成报告记录此选择。
- 工具只在当前仓库内检索（`repo_papers ⋈ paper_chunks`，含归档、不含已移除），
  参数仅 `query`/`limit`，`repo_id` 闭包绑定；工具内**自开 session**，不复用请求级 session。
- 证据编号由服务端稳定分配 + `chunk_id` 去重，引用校验只认这个列表。
- 流前错误：404 / 409 `repo_empty`（含“有论文但无 chunk”）/ 503 `llm_unavailable`；**没有 403**。
- `/messages` 只返回当前用户自己的对话（私有仓库创建者/管理员同样如此）。

**验证**：`pytest -q tests/api/test_repo_chat.py` → 13 passed。

## 已知边界（D4）

4. 私有仓库转公开后，历史对话的可见性立即按公开规则收敛（非发起者 404），这是契约要求，不是 bug。
