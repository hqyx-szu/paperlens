### 关键决策

- **缓存键**：`paper_id + level + content_hash + prompt_version + model`，与契约 §8.4 一致；
  `INSERT ... ON DUPLICATE KEY UPDATE` 实现“后写为准”，并发重复生成不会报错。
- **引用复用对话的校验器**：四维正文里写 `[n]`，用 `validate_answer_citations()` 统一清理/重排编号，
  citations 只来自该论文自身的 chunk（`quote` 是 chunk 真实子串）。
- 字段缺失/空字符串 → `论文未明确说明`（不是 null，不是 502）；模型输出无法解析 → `502 llm_failed`。
- 模型不可用 → `503 llm_unavailable`（`get_llm_client()` 在写库前抛出）；论文没有片段 → `409 paper_not_ready`；
  论文不存在/非 ready → `404 paper_not_found` 优先于 `summary_not_generated`。
- 归档论文仍可生成与读取；`available_summary_levels` 只返回**当前 content_hash/prompt_version/model** 下已缓存的档位，
  因此提示词或模型变化后旧档位自动“消失”（旧行保留，不参与展示）。

## 2026-10-29 变更：`force` 重新生成（契约 1.3）

**问题**：前端在 GET 成功后把按钮改成「重新生成」，但 `POST /summaries/generate` 按 §8.5 是缓存优先，
点击后命中缓存返回旧内容、页面无变化也无提示 —— 属于前后端语义不一致，不是报错。

**改动**：

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 契约 | `doc/API接口文档（V1.0）.md` §8.5、§19 | `SummaryGenerateRequest` 增加 `force`（bool，默认 `false`）；`true` 跳过缓存、重新生成并覆盖同一缓存键；缓存键/错误码/60 秒超时不变；变更记录 1.3 |
| 契约 | `doc/paperlens-openapi.json` | `SummaryGenerateRequest.properties.force` + 生成接口 description 补充 force 语义 |
| 后端 | `app/schemas/paper.py` | `force: bool = False`（`extra="forbid"` 仍生效） |
| 后端 | `app/services/summaries.py` | `generate_summary(..., force=False)`：`force=True` 时跳过 `get_cached_summary()`；写库仍走 `ON DUPLICATE KEY UPDATE`，天然覆盖同一缓存键 |
| 后端 | `app/api/v1/endpoints/papers.py` | 透传 `payload.force` |
| 前端 | `web/app/index.html` | 按钮三态 `load / create / force`；`force` 时先二次确认再 POST `{level, force:true}`；成功 toast「已重新生成，并覆盖该档位缓存」；面板加缓存说明行 |
| 测试 | `tests/api/test_paper_summaries.py` | 新增 `test_force_regenerate_bypasses_cache`：第一次生成 → force 第二次（模型调用数 2、内容更新）→ GET 读到新内容 → 不带 force 再生成（仍 2 次调用，命中缓存） |

**行为边界**：`force` 不改变权限、错误码与 60 秒超时；并发 force 仍可能重复生成，最终以后写为准；
`force=true` 时若模型不可用仍返回 `503 llm_unavailable`（不会回退到旧缓存）。
