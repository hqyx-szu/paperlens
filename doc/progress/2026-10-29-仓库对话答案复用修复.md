# 仓库对话“答不出来”修复：完成报告

> 日期：2026-10-29 ｜ 范围：`app/services/repo_chat.py`、`app/services/chat_stream.py`、`tests/api/test_repo_chat.py`
> 结论：问题真实存在，且是**答案被二次生成覆盖**，不是检索或数据问题。已按 A+B 修复并用真实模型复验。

## 复现（改前）

- 开发库仓库 2 篇 `ready`、99 chunks / 99 embeddings，向量模型可用。
- 问“这个仓库包含了哪些论文”：Agent 调 `search_repo` 两次，给出带编号的正确回答，
  经 `validate_answer_citations` 仍保留 6 条有效引用 —— 然后这份答案被丢弃。
- `repo_chat_events()` 随后无条件 `build_chat_messages()` + `FINAL_ANSWER_SUFFIX` 二次生成，
  第二次只有随机片段、没有仓库成员清单，输出变成固定拒答：
  “根据当前资料，没有足够证据回答这个问题。”

用 `FakeLLMClient` 复现（工具阶段回答带 [1]、stream 返回拒答）：
`tokens` 是拒答、`fake.stream_calls` 有 1 次 —— 与线上现象一致。

## 根因

| 位置 | 问题 |
| --- | --- |
| `repo_chat.py:277`（改前） | `await run_tool_loop(...)` 返回值被丢弃，Agent 最终答案没接住 |
| `repo_chat.py:312-334`（改前） | 循环结束后无条件二次生成，等于覆盖 Agent 已答对的内容 |
| `chat.py` 通用 `CHAT_SYSTEM_PROMPT` | 二次生成只有片段、没有仓库成员清单，元问题必拒答 |
| `chat_stream.py` 无引用重试 | 能力类问题天然没有论文引用，必被改成固定拒答 |

## 修复

### A. 复用 Agent 已通过引用校验的答案

- `messages = await run_tool_loop(...)`，用 `last_assistant_content()` 取最后一条非空 assistant。
- `validate_answer_citations(answer, evidence)`：
  - 有有效引用 → `stream_answer_events(answer, citations, conversation_id)` 直接输出（**不再调用模型**）；
  - 拒答文案 → 复用该文案，`citations=[]`，并用 `CITATION_RE` 清掉正文残留的 `[n]`（否则前端会出现悬空角标）；
  - 无有效引用且非拒答 → 回退到原 `build_chat_messages + answer_events` 路径，拒答/重试规则不变。
- `chat_stream.py` 新增 `stream_answer_events()`（落库 → citation → token → done），
  `answer_events()` 尾部改为复用它，行为等价。

### B. 能力类问题走固定回答

- `is_capability_question()`：短问题（≤60 字）且命中中英文措辞（你能回答什么/你能做什么/你是谁/
  what can you do/who are you…），避免误伤“这个方法怎么用”这类论文内容问题。
- 命中后 `meta` 之后直接输出 `REPO_CAPABILITY_TEXT`（能做什么 + 只读/不跨仓库/不联网限制），
  `citations=[]`、`status=complete`，**不进入工具循环、不调用模型**。
- 依据契约 §11.1.1.6：建议/过渡性语句不需要引用；能力说明不是论文事实陈述。

### C. 未做（可选增强）

“精确全集”仍取决于检索：模型可能说“至少包含”。要做权威清单需给 Agent 注入仓库成员元数据
或加 `list_repo_papers` 工具；本期未做，避免扩大改动面，已在边界里记录。

## 影响面

- 不改数据库迁移、API 契约、OpenAPI、前端页面；SSE 事件顺序仍是 `meta → citation* → token* → done`。
- 会话（`/sessions/{id}/chat/stream`）与单篇（`/papers/{id}/chat/stream`）走 `chat_events`，
  行为不变（`answer_events` 仅做了尾部等价重构，测试全绿）。
- 成本下降：仓库对话在“Agent 已答对”时少一次模型调用；能力问题完全不调模型。

## 已知边界

- 仓库里有超过 8 条片段时，Agent 只能看到 `search_repo` 返回的前 8 条，回答可能用“至少”措辞。
- 能力问题是固定文案，不随模型能力变化；改文案改 `REPO_CAPABILITY_TEXT` 即可。
- `search_repo` 的检索质量仍取决于 ngram/向量召回；与本次问题无关。
