## 2. 角色与权限

- 角色值：`reader`（默认）、`admin`。
- 所有 `/api/v1/admin/*` 路由级依赖 `require_admin`。
- `GET /auth/me`、登录响应均返回 `role`，角色变更在下一次请求生效。
- 停用用户：删除其全部 `user_sessions`，旧 Cookie 立即 401；停用账号登录统一返回
  `401 invalid_credentials`（不再返回旧版 403 `user_disabled`）。
- 管理员自保护：
  - 不能把自己降为 `reader` → 400 `cannot_demote_self`
  - 不能停用自己 → 400 `cannot_disable_self`
  - 不能移除最后一个可用管理员 → 400 `last_admin`
  - 三个规则按上述顺序判定。

## 3. 管理后台接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/admin/users` | `q`（≤200，字面量匹配邮箱/显示名）、`page`、`page_size`（1–100），`id DESC` |
| POST | `/api/v1/admin/users` | 201；邮箱转小写；显示名为空时取邮箱前缀并截断 64；重复邮箱 409 |
| PATCH | `/api/v1/admin/users/{user_id}` | 改显示名/角色/启停；空对象 400；`role`/`is_active` 为 `null` 返回 422 |
| POST | `/api/v1/admin/users/{user_id}/reset-password` | 204；撤销该用户全部会话 |
| GET | `/api/v1/admin/stats` | 用户总数/启用数；论文、仓库计数暂为 0 |

搜索使用 `LIKE` 并转义 `%`、`_`、`\`，搜索词按字面量处理。
列表分页超出最大页返回 200 + 空数组。

## 4. AI 公共层

```text
app/core/ai/
├── client.py      # LLMClient / DeepSeekClient / get_llm_client
├── streaming.py   # sse() / sse_response() / with_heartbeat()
├── tools.py       # ToolSpec / ToolRegistry / run_tool_loop()
└── prompts.py     # SYSTEM_PROMPT / REFUSAL_TEXT / Citation / citations_are_valid()
```

设计要点：

- 客户端懒加载：`DeepSeekClient` 在实例化时校验 API Key，未配置返回
  `503 llm_unavailable`，不影响应用启动。
- 错误映射：超时 504 `llm_timeout`；连接/鉴权失败 503 `llm_unavailable`；
  其他上游错误 502 `llm_failed`；429/5xx 最多重试 1 次（指数退避），400 不重试。
- 工具阶段非流式：`run_tool_loop` 只负责调用工具，最终回答由调用方流式输出，
  避免“流式 + tool_calls 增量解析”的复杂度。
- 工具范围由服务端闭包绑定（`repo_id` / `session_id` 不进入模型参数）。
- 工具循环超限 → `504 tool_loop_exceeded`；未知工具 → `unknown_tool`。
- 引用规则：编号从 1 开始连续；回答中出现未定义编号或没有引用均判无效；
  固定拒答文案为“根据当前资料，没有足够证据回答这个问题。”
- SSE 事件格式：`event: <name>\ndata: <json>\n\n`；空闲 15 秒发送 `: ping` 心跳。
- 只记录 token 用量与模型名，不记录完整提示词和用户原文。

配置项（`.env`）：

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
LLM_TIMEOUT_SECONDS=60
LLM_MAX_TOOL_STEPS=4
LLM_MAX_OUTPUT_TOKENS=2048
```

## 5. 契约对齐修正

| 差异 | 处理 |
| --- | --- |
| `POST /auth/register` 存在 | 删除接口与 `RegisterRequest`，更新测试 |
| 停用账号登录 403 | 统一 401 `invalid_credentials` |
| 时间无 `Z` | `UTCDatetime` 统一序列化为 `YYYY-MM-DDTHH:MM:SSZ` |
| 错误 `details` 被省略 | 始终返回，空值为 `null` |
| `LoginRequest.email` 无上限 | 增加 `max_length=255` |
| `BaseHTTPMiddleware` 可能缓冲 SSE | 改为纯 ASGI `RequestContextMiddleware` |
| conftest 写死清表 | 改为按 `Base.metadata.sorted_tables` 动态 TRUNCATE |

## 7. 运行方式

```bash
uv sync
cp .env.example .env      # 填写数据库连接（本地 MySQL 服务端口为 3307）
uv run alembic upgrade head
uv run python -m scripts.create_admin --email admin@example.com
uv run uvicorn app.main:app --reload
```

打开 http://127.0.0.1:8000/admin 进入管理后台（未登录会显示登录表单）。

## 8. 已知边界

- `GET /admin/stats` 的论文/仓库计数在 D2/D4 模型合并前固定为 0。
- 管理后台页面目前是零构建单文件版（`web/admin/index.html`），随 FastAPI 同源提供；
  D5 前端脚手架（React + Vite）就绪后可替换，接口契约不变。
- 流式接口需由 D3/D4 在路由层捕获 `AppError` 并转换为 `event: error`。
- `with_heartbeat` 已提供，但具体 SSE 路由由 D3/D4 组装。
