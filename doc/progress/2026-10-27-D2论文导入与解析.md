## 2. 数据模型与迁移

- `papers`：标题、作者 JSON、年份、venue、`MEDIUMTEXT` 摘要、DOI、内容哈希、
  状态、归档、错误信息、创建/更新时间。
- `paper_files`：一论文一文件；`paper_id`、`sha256` 唯一；保存原始文件名、
  根目录相对路径、大小、MIME、上传时间。
- `paper_chunks`：`paper_id + chunk_index` 唯一；页码从 1 开始；保存正文与字符数。
- `0003_papers`：按 `papers → paper_files → paper_chunks` 建表；降级按反序删表。
- 摘要使用 MySQL `MEDIUMTEXT`；两个 FULLTEXT 索引均显式 `WITH PARSER ngram`。

## 3. API 交付

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/admin/papers/import` | 批量导入；202；items 顺序与上传一致 |
| GET | `/api/v1/admin/papers` | `q`/`status`/`archived`/分页；`created_at DESC, id DESC` |

| POST | `/api/v1/admin/papers/{id}/retry` | 仅 failed 且未归档；原子置 queued；202 |
| POST | `/api/v1/admin/papers/{id}/archive` | 仅 ready；幂等；不改变 `archived_at` |
| GET | `/api/v1/papers` | ready 未归档；≥2 字走 ngram FULLTEXT，单字走 LIKE |
| GET | `/api/v1/papers/{id}` | ready 可查（含归档）；返回 `has_file/can_download/can_chat` |
| GET | `/api/v1/papers/{id}/download` | ready 可下载；`filename*` RFC 5987 + ASCII fallback |

`/admin/papers/import` 注册在 `/{paper_id}` 之前，避免被 ID 路由捕获。
所有管理端错误码保持 D1 风格：401 `unauthorized`、403 `forbidden`、
404 `paper_not_found`/`file_not_found`、409 `invalid_state`、413 `file_too_large`。

## 4. 解析、存储与后台任务

- 解析固定使用 `pypdf.PdfReader`，逐页 `extract_text()`；不引入 PyMuPDF/OCR。
- 文本规范化去 NUL、统一换行、压缩水平空白、最多保留一个空行。
- 标题优先 `/Title`，再首行/文件名兜底；作者按逗号/分号/顿号/and 切分；
  年份排除 DOI/arXiv 行；摘要截到 Introduction/Keywords；DOI 去尾标点。
- 内容哈希为逐页文本按 `\n` 拼接后的 SHA-256，供 D5 复用。
- 分块按页独立，目标 1000、重叠 150、最小 50、最大 2000；
  相邻块保留精确 150 字符重叠。
- 上传按 1MB 流式读取，临时文件在存储根 `.tmp/`；`promote` 使用 `os.replace`。
- 请求级失败（超出总量）清理本请求全部临时文件；单文件拒绝不影响整批。
- 后台使用 FastAPI `BackgroundTasks` + `process_paper()`；原子 `UPDATE ... WHERE status='queued'`
  保证并发幂等；事件循环不被解析阻塞（`asyncio.to_thread`）。
- 启动 lifespan 调用 `recover_stale_papers()`，只处理超时 `parsing/indexing`，
  固定原因“处理中断，请重试”；数据库异常只 warning，不阻止启动。
- 判重分两级：导入时按文件 SHA-256（契约口径，命中即 `duplicate=true` 并复用论文）；
  解析完成后用正文 `content_hash` 复核，若与另一篇未归档 `ready` 论文相同，
  该次处理以 `failed` +「与已有论文重复：《标题》（ID n）」结束，且不写入 chunks。

## 8. 已知边界与后续接口

- 进程内 BackgroundTasks 不持久；崩溃恢复只覆盖超时 `parsing/indexing`，
  `queued` 若在崩溃前未开始可能停留（D2 接受）。
- 仅支持 PDF 文本层；扫描件/图片型 PDF 明确失败，不做 OCR。
- 管理员可手工修正自动提取质量差的元数据；DOI 不通过 PATCH 修改。
- 用户目录的单字搜索走 LIKE；ngram 默认 token 为 2，D3/D4 复用需保持该回退。
- `available_summary_levels` 固定 `[]`，D5 建 `paper_summaries` 后接回。
- `AdminStats.repos_*` 保持 0，D4 表落地后接回。
- `visible_paper_conditions()` 是 D3/D4 新搜索/仓库入口的唯一可见性来源。
- 同一论文的不同 PDF 副本（重新下载/重新导出）不会被文件哈希识别；正文哈希复核只覆盖
  “文本完全一致、仅字节不同”的副本，排版/分页/文字有改动的版本仍会各成一篇。
  DOI、标题相似度、向量近似判重均留待 V1.1。
- 判为重复的论文状态是 `failed`；契约规定 `archive` 只接受 `ready`，因此这类记录不能归档，
  会留在管理列表中作为“已识别重复”的提示，管理员可忽略，或 retry（会再次判重）。
- 正文哈希复核是“先查后写”，两篇内容相同的新论文并发解析存在小概率都进入 `ready`
  （进程内 BackgroundTasks、无分布式锁），属 D2 已知边界。
