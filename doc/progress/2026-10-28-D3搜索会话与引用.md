## 2. 数据模型

新增五表（迁移 `0004_sessions_chat`）：

- `search_sessions`：查询词、类型、论文/证据计数、系统消息快照、创建时间。
- `session_papers`：会话论文 ID + rank；唯一 `(session_id, paper_id)`。
- `session_evidence`：chunk ID、页码、quote 快照 + rank；唯一 `(session_id, chunk_id)`。
- `conversations`：`(user_id, scope_type, scope_id)` 唯一；D3 使用 `session`/`paper`，`repo` 预留给 D4。
- `messages`：role/content/status/citations JSON；`status` 默认 `complete`。

`messages` 使用 `(conversation_id, id)` 复合索引支撑游标分页；所有外键 `ON DELETE CASCADE`。

## 4. 检索与引用决策

- 检索层集中在 `app/services/search.py`，后续可替换为 Qdrant；D3 不做翻译/embedding。
- 正文 chunk 命中优先；全部未命中时回退标题/摘要，并取命中论文前 2 个 chunk 作为证据。
- 会话对话只读 `session_evidence` 快照；单篇对话所有查询带 `paper_id`，不会跨论文。
- 回答完整缓冲后校验：`[n]` 必须在证据范围内且 quote 是 chunk 真实子串；按正文首次出现重排，重复编号复用，最多 12 条。
- 无有效引用时重试一次；仍无则保存固定拒答文案，citations 为空。
- 流前 404/409/422/503 返回普通 JSON 且不写消息；流中错误保存 `error`；断线尽量保存 `stopped`（后台任务 + 轮询测试）。

## 6. 已知边界

1. ngram FULLTEXT 是词面匹配，不是语义检索；单字 LIKE 可能慢。
2. 首字延迟来自“缓冲完整回答再发 token”，这是引用正确性的取舍。
3. 停止消息使用后台任务尽力保存；进程崩溃/强制断网可能丢失最后一条 `stopped`。
4. `related_repo_count=0`、四维视图占位；D4/D5 接回。
5. `/app` 是临时演示页，不是 D5 正式前端；API 不变。
6. 管理员不能读取他人会话；D4 私有仓库对话另行走权限。
7. 无 PDF OCR、扫描件、Word 解析；PDF 查询只取文本层。
