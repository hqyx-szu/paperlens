## 0. 本文件的使用规则（后续开发必须遵守）

1. **每次开始写代码前先读本文件**；按 §8 的任务顺序执行，不跳项、不提前实现 D3/D4/D5。
2. 每完成一个任务，立即更新本文件的复选框和“实际变更”，再进入下一项。
3. 每个任务结束必须跑：
   - `uv run ruff check .`
   - 该任务对应的定向测试
   最后跑全量 `uv run pytest -q`。
4. 所有测试必须**串行执行**。测试库 `paperlens_test` 是共享状态，禁止同时启动两个 pytest 进程。
5. 禁止在应用启动时 `create_all()`；schema 只能通过 Alembic 迁移变更。
6. 禁止把 `var/`、`.env`、测试 PDF、真实 API Key 提交到 Git。
7. 若实现与 `doc/API接口文档（V1.0）.md` 冲突，以 API 文档为准；确实需要改契约时，先修改本文件并说明原因，再改 API 文档，最后改代码。
8. 本阶段只做“管理端论文导入 + 文本层解析 + 用户端目录/详情/下载”。不做 OCR、图片型 PDF、PDF 查询接口（D3）、四维生成（D5）、仓库（D4）。
9. PDF 解析引擎固定为 **`pypdf`**（BSD，纯 Python，适合文本层提取）；禁止引入 PyMuPDF（AGPL/商业许可风险）。测试 PDF 用 **`reportlab`** 仅作为 dev 依赖生成。
10. 任何失败原因写入数据库前都必须转成用户可读文本；不得包含堆栈、SQL、服务器路径。

## 2. D2 目标与明确不做的事

### 2.1 目标

1. 管理员可以一次上传 1–20 个 PDF，单文件 ≤20 MB，单次总大小 ≤100 MB。
2. 按 SHA-256 去重；同一文件不重复创建、不重复存储。
3. 后台异步完成：`queued → parsing → indexing → ready`，任一阶段失败进入 `failed`。
4. 从 PDF 文本层提取标题、作者、年份、期刊/会议、摘要、DOI，并建立带页码的原文片段。
5. 管理员可以列表筛选、查看详情、修正元数据、重试失败论文、归档就绪论文。
6. 登录用户可以搜索就绪且未归档论文、查看详情、下载原文；归档论文仍可被直接查看/下载。
7. 服务重启时把超时的 `parsing/indexing` 标记为失败，原因固定为「处理中断，请重试」。
8. 管理后台静态页增加“论文目录”页签，能完成上述管理动作。

### 2.2 不做

- 不做 OCR、扫描件、图片型 PDF、复杂版式恢复。
- 不做 PDF 查询 `/search/pdf`（D3）。
- 不做全局检索的语义排序、向量库、四维总结（D3/D5）。
- 不做论文文件替换、用户上传、物理删除。
- 不做仓库计数（D4，`AdminStats.repos_*` 继续为 0）。
- 不做多进程任务队列、Celery、Redis；D2 使用进程内后台任务 + 启动恢复。

## 3. 已锁定的设计决策

| 决策点 | 固定方案 |
| --- | --- |
| PDF 解析 | `pypdf.PdfReader`；逐页 `extract_text()` |
| 测试 PDF 生成 | `reportlab`，只放 dev 依赖 |
| 存储根目录 | `PAPER_STORAGE_DIR`，默认 `var/papers` |
| 存储相对路径 | `<paper_id>/<sha256>.pdf`（相对存储根） |
| 文件上传临时区 | `<PAPER_STORAGE_DIR>/.tmp/` |
| 去重键 | `paper_files.sha256` 全局唯一 |
| 状态存储 | `papers.status` 字符串，值由 `PaperStatus` 约束 |
| 全文索引 | MySQL FULLTEXT + `WITH PARSER ngram`；论文标题/摘要、chunk 正文各一个 |
| 后台任务 | FastAPI `BackgroundTasks` + 进程内 `process_paper(paper_id)`；启动恢复兜底 |
| 分块 | 每页独立切块；目标 1000 字符、重叠 150 字符、最小 50 字符、单块不超过 2000 字符 |
| 页码 | 从 1 开始；无法确定时为 `null`（本实现总是有页号） |
| chunk 序号 | `chunk_index` 从 0 开始，同一论文唯一 |
| 摘要上限 | 20000 字符；数据库用 `MEDIUMTEXT` |
| 作者 | `JSON` 数组，最多 50 个，每项 1–200 字符 |
| 管理员列表排序 | `created_at DESC, id DESC` |
| 用户目录排序 | 有 q：相关度降序 + `id DESC`；无 q：`id DESC` |
| 归档 | 只改 `is_archived/archived_at`，不改 `status`，不物理删除 |

### 6.2 `app/services/paper_parser.py`

```python
class PdfParseError(Exception):
    code: Literal["corrupt", "encrypted", "no_text_layer"]
    user_message: str


@dataclass(frozen=True, slots=True)
class ParsedChunk:
    page: int | None
    content: str
    char_count: int


@dataclass(frozen=True, slots=True)
class ParsedPaper:
    title: str
    authors: list[str]
    year: int | None
    venue: str | None
    abstract: str | None
    doi: str | None
    content_hash: str
    chunks: list[ParsedChunk]


def extract_pdf_pages(path: Path) -> list[tuple[int, str]]: ...
def parse_pdf(path: Path, *, fallback_title: str) -> ParsedPaper: ...
```

实现约束：

- `extract_pdf_pages` 是同步 CPU/IO 函数，处理流程中用 `asyncio.to_thread(...)` 调用，禁止阻塞事件循环。
- `pypdf.PdfReader`：加密 PDF 先尝试空密码 `decrypt("")`；失败抛 `PdfParseError("encrypted", "PDF 已加密，无法解析")`。
- 损坏/无法打开抛 `PdfParseError("corrupt", "文件已损坏，无法解析 PDF")`。
- 所有页都没有有效文本抛 `PdfParseError("no_text_layer", "PDF 没有可提取的文本层（扫描件/图片型 PDF 暂不支持）")`。
- 文本规范化：去 NUL、统一换行、压缩水平空白、最多保留一个空行；不改变中英文内容。
- `content_hash`：对规范化后的全文按页拼接（页间 `\n`）做 SHA-256，十六进制 64 字符；D5 复用它做缓存键。
- 标题：优先 PDF `/Title`；无效时取第一页第一个有意义的短行；再退回 `fallback_title`；最终空值用「未命名论文」，截断 500。
- 作者：优先 `/Author`，按 `,`、`;`、`、`、` and ` 切分、去空、去重；最多 50 个，每项最多 200；无元数据时尝试标题后的 1–3 个短行。
- 年份：先在前两页找 `(19|20)\d{2}`，范围 1900–2100，排除 DOI/arXiv 行中的数字；没有再尝试 PDF 创建日期。
- venue：优先 `/Subject`（当它像期刊/会议名），否则前 3 页匹配 `Proceedings|Conference|Journal|Transactions|Symposium|Workshop|arXiv|IEEE|ACM|NeurIPS|ICML|ICLR|CVPR|ACL` 的短行；否则 `null`。
- 摘要：前 3 页找 `Abstract` / `摘要` 标题，截到下一个 `Introduction` / `1 Introduction` / `Keywords` / `关键词` / `引言`；上限 20000。
- DOI：匹配 `10.\d{4,9}/[-._;()/:A-Za-z0-9]+`，去掉尾部标点，上限 255。
- 分块：每页独立；目标 1000、重叠 150、最小 50、最大 2000；尽量在换行/中文句号/英文句点处断开；页码从 1 开始；`chunk_index` 从 0 连续递增。
- 禁止 OCR；空页跳过；至少一个有效 chunk 才允许解析成功。

### 6.3 `app/services/paper_storage.py`

```python
MAX_FILE_BYTES = 20 * 1024 * 1024
MAX_BATCH_FILES = 20
MAX_BATCH_BYTES = 100 * 1024 * 1024


class BatchTooLarge(Exception):
    """本次请求总大小超过上限。"""


@dataclass(slots=True)
class StagedUpload:
    display_name: str
    tmp_path: Path | None
    size: int
    sha256: str | None
    rejection: str | None


class PaperStorage:
    def __init__(self, root: Path) -> None: ...
    @property
    def root(self) -> Path: ...
    def relative_path(self, paper_id: int, sha256: str) -> str: ...
    def absolute_path(self, relative: str) -> Path: ...
    def exists(self, relative: str) -> bool: ...
    def promote(self, tmp_path: Path, relative: str) -> None: ...
    def remove(self, relative: str) -> None: ...
    async def stage(
        self,
        upload: UploadFile,
        *,
        already_bytes: int,
        max_batch_bytes: int | None = None,
    ) -> StagedUpload: ...


def safe_basename(filename: str | None) -> str | None: ...
```

行为要求：

- `root` 相对路径按当前工作目录解析（README 要求从仓库根目录运行）。
- `absolute_path` 必须 `resolve()` 后校验在 `root` 内；数据库中的异常路径不能穿越到根目录外。
- `exists(relative)` 捕获 `ValueError`/`OSError` 并返回 `False`；用户详情里的 `can_download` 不能因为坏路径抛 500。
- `stage` 用 1 MB 分块读，边写临时文件边算 SHA-256 和总字节；临时文件放在 `root/.tmp/`。
- `max_batch_bytes is None` 时在函数内部读取 `MAX_BATCH_BYTES`（不要在函数定义时绑定默认值，否则测试 monkeypatch 无效）。
- 读取过程中若 `already_bytes + size > max_batch_bytes`，立即关闭并删除临时文件，抛 `BatchTooLarge`；导入接口捕获后清理本请求全部临时文件并返回 413。
- 单文件超 20 MB、空文件、`Content-Type` 不是 `application/pdf`、文件头不是 `%PDF-`、basename 为空/`.`/`..`/含 NUL/超过 255 字符，均**只拒该项**，写 `rejection`，并删除临时文件。
- `display_name` 为 basename；basename 无法得到时用 `""`，保证响应 `filename` 仍是字符串。
- `promote` 先创建父目录，再 `os.replace`；目标已存在时覆盖（仅用于并发/崩溃后的同哈希路径）。
- `remove` 只删除存储根内的文件，忽略 `FileNotFoundError`。

```python
async def recover_stale_papers() -> int: ...
```

`process_paper` 固定流程：

1. 用 `get_session_factory()` 开独立 session（不能复用请求 session）。
2. 原子认领：
   `UPDATE papers SET status='parsing', updated_at=:now WHERE id=:id AND status='queued'`；
   `rowcount == 0` 直接返回（已被其他任务处理/已就绪/已失败）。
3. 提交后读取论文与文件记录；文件缺失 -> 标记失败「文件不存在，请重试」。
4. `parsed = await asyncio.to_thread(parse_pdf, path, fallback_title=paper.title)`。
5. 解析成功后置 `status='indexing'` 并提交。
6. 在索引事务中：
   - `DELETE FROM paper_chunks WHERE paper_id=:id`（重试时替换旧片段）；
   - 每 500 条批量插入新 chunks；
   - 更新元数据：`title/authors/year/venue/abstract/doi/content_hash`；
   - `status='ready'`、`error_message=None`、`updated_at=now`；
   - 最后一次 commit。只有全部成功后才允许 `ready`。
7. 任一步失败：
   - `PdfParseError` 使用其 `user_message`；
   - 其他异常记录 `logger.exception`，数据库只写「解析失败，请重试」；
   - 用独立 `UPDATE` 置 `failed`、`error_message=...`、`updated_at=now`；不得保存堆栈/路径。
8. 处理过程必须幂等：同一 `paper_id` 多任务并发时，只有原子认领成功者继续。

`recover_stale_papers`：

- 查询 `status IN ('parsing','indexing')` 且 `updated_at < utcnow() - PAPER_PROCESSING_TIMEOUT_MINUTES` 的论文。
- 批量更新为 `failed`，`error_message = "处理中断，请重试"`，`updated_at=utcnow()`，返回更新行数。
- 不处理 `queued`、`ready`、`failed`。
- 在 `app/main.py` 的 lifespan 启动阶段、`yield` 之前调用；数据库异常只记录 warning，不阻止应用启动。
- 测试直接调用该函数，不依赖 FastAPI lifespan。

#### `POST /api/v1/admin/papers/import`

签名：

```python
@router.post("/import", response_model=ImportResponse, status_code=202)
async def import_papers(
    background_tasks: BackgroundTasks,
    db: Annotated[AsyncSession, Depends(get_db)],
    files: Annotated[list[UploadFile], File()],
) -> ImportResponse: ...
```

固定处理顺序：

1. `files` 为空或数量不在 1–20 -> `AppError(422, "validation_error", "请上传 1–20 个 PDF 文件")`。
2. 逐个 `storage.stage(...)`；累计字节。`BatchTooLarge` -> 清理本请求全部临时文件，`AppError(413, "file_too_large", "上传文件总大小超过 100MB")`。
3. 对每个 `StagedUpload` 按上传顺序处理：
   - 有 `rejection`：生成拒绝项（`paper_id/status=None`、`duplicate=False`、`is_archived=False`），计数 `rejected`，删除临时文件，继续。
   - 按 `sha256` 查已有 `PaperFile`：
     - 存在：删除临时文件，生成 duplicate 项，沿用已有状态/归档标志，计数 `duplicates`；不自动重试，不移动文件。
     - 不存在：创建 `Paper`（`title=filename 去扩展名`，空则「未命名论文」，`authors=[]`，`status=queued`），`flush()` 拿 id；计算相对路径并 `promote`；创建 `PaperFile`；`commit()`。
       - 若 commit 因 `sha256` 唯一索引冲突：`rollback()`、删除已 promote 的文件、按 duplicate 重新查询；计数 `duplicates`。
       - 其他异常：删除已 promote 文件并抛出。
   - 新创建项：`status=queued`，计数 `created`，把 `paper.id` 加入待处理列表。
4. 对整个处理使用 `try/finally`：清理所有仍存在的 `StagedUpload.tmp_path`；promote 成功后 tmp 已不存在，不能误删最终文件。
5. 对每个新建 id 调用 `background_tasks.add_task(process_paper, paper_id)`。
6. 返回 `202`；`items` 数量与顺序必须等于上传文件；`created + duplicates + rejected == len(items)`。
7. 即使全部 rejected，也返回 202。

文件名规则：

- 显示名取 basename；`../../a.pdf` -> `a.pdf`；Windows 反斜杠也当分隔符处理。
- 初始标题 = 显示名用 `rsplit(".", 1)[0]` 去掉最后一个扩展名（`paper.tar.gz` -> `paper.tar`，`.pdf` -> 空）；截断 500；为空用「未命名论文」。
- 不直接加入任何仓库。

#### `GET /api/v1/admin/papers`

- Query：`q`（≤200，空/全空白不过滤）、`status`（`PaperStatus|None`）、`archived`（`bool|None`）、`page`（≥1）、`page_size`（1–100，默认 20）。

- `model_fields_set` 为空 -> `400 bad_request`。

#### `POST /api/v1/admin/papers/{paper_id}/retry`

- `404 paper_not_found`。

- `rowcount == 0` -> `409 invalid_state`（非 failed 或已归档）。
- 成功后 `background_tasks.add_task(process_paper, paper_id)`，返回 `202 AdminPaperDetail`。
- 保留文件；重试成功后替换 chunks 和自动元数据。

## 10. 风险、边界与后续接口

| 风险/边界 | 处理 |
| --- | --- |
| 进程内 BackgroundTasks 不持久 | 崩溃恢复只覆盖 `parsing/indexing`；`queued` 若在崩溃前未开始会停留，D2 接受；后续可换任务队列 |
| 扫描件无文本 | 明确失败，不做 OCR |
| PDF 元数据质量差 | 用文件名/首行/正则兜底；管理员可手工修正 |
| 大 PDF 解析阻塞 | `asyncio.to_thread`；单文件上限 20MB |
| 归档后手工删除文件 | `can_download=false`，下载 404 `file_not_found`；不自动修复 |
| MySQL ngram 单字检索 | 单字 q 走 LIKE 回退；双字及以上走 FULLTEXT |
| D5 四维缓存 | D2 `available_summary_levels=[]`；D5 新增 `paper_summaries` 后接回 |
| D4 仓库计数 | `repos_*` 保持 0；D4 接回 |
| 管理 UI 静态页 | 只做 D2 必需操作，不做完整前端工程化 |

**给后续模块的接口**：

- D3 PDF 查询：调用 `extract_pdf_pages`，只提取文本，不保存文件/不入库；最多 50 页、前 2000 字符由 D3 截取。
- D3/D4 可见性：统一调用 `visible_paper_conditions()`。
- D3 引用：使用 `paper_chunks.page`、`paper_chunks.content`、`paper_chunks.id`；`page` 从 1 开始。
- D5 缓存键：使用 `papers.content_hash + prompt_version + model`。
